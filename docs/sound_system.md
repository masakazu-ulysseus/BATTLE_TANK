# サウンドシステム仕様書

## 背景・課題

v2.1 時点のサウンドシステムには以下の問題があった。

1. **ゲーム中にSEがほぼ聞こえない（バグ）**
   - Pyxel は同一チャンネルで `play()` すると再生中の音を即座に上書きする。
   - エンジン音が移動キー押下中ずっと ch0 を占有し、ch0 で再生される発射音を上書きしていた。
   - 爆発・被弾・敵撃破が全て ch1 に集中し、互いに切り合っていた。
2. **エンジン音が可聴域外（バグ）**
   - `c0`（約16Hz）はほぼ聞こえず、「チャンネルを占有するのに本人は聞こえない」状態だった。
3. **発射音の不整合（バグ）**
   - `player.py` が発射ボタン押下だけで（弾数制限で撃てない時も）発射音を再生していた。
   - 実際の発射時に `game_manager.py` が鳴らしていたのは発射音ではなく爆発音（sound 2）だった。
4. **ゲーム中BGMなし（仕様）**
   - 本家バトルシティーもプレイ中の常時BGMはないが、本家にあるステージ開始ジングルが存在しなかった。

## 方針

本家バトルシティー準拠とする:
- プレイ中の常時BGMは**なし**
- **ステージ開始時にジングル**（ファンファーレ）を再生
- 移動中は**エンジン音**が鳴り続ける（可聴域・控えめな音量）
- SEはチャンネルを役割別に分離し、上書き競合を解消する

## チャンネル割り当て

| チャンネル | 定数 | 用途 |
|---|---|---|
| 0 | `SOUND_CHANNEL_ENGINE` | エンジン音（移動中）専用 |
| 1 | `SOUND_CHANNEL_FIRE` | 発射音専用 |
| 2 | `SOUND_CHANNEL_EXPLOSION` | 爆発・被弾・敵撃破・弾相殺 |
| 3 | `SOUND_CHANNEL_ITEM` | アイテム取得・パワーアップ・ジングル類 |

- タイトルBGM（`musics[1]`、ch0-2使用）・ゲームオーバーBGM（`musics[2]`）はSEが鳴らない画面でのみ再生されるため競合しない。

## サウンドID一覧

| ID | 内容 | 再生チャンネル | 備考 |
|---|---|---|---|
| 0 | エンジン音 | 0 | `c2/d2` の低音ワーブル、音量控えめ。8フレーム周期で再トリガーし連続音化 |
| 1 | 発射音 | 1 | 実際に弾が発射された時のみ再生（game_manager 経由） |
| 2 | 爆発音 | 2 | 壁破壊・被弾・弾相殺 |
| 3 | アイテム取得音 | 3 | |
| 4 | ステージクリア音 | 3 | |
| 5 | ゲームオーバー音 | 2 | |
| 6 | パワーアップ音 | 3 | |
| 7 | 敵撃破音 | 2 | |
| 8 | ステージ開始ジングル | 3 | 新規追加。ステージ開始・次ステージ進行時に再生 |
| 12-15 | タイトル/ゲームオーバーBGM素材 | - | `musics[1]`, `musics[2]` |

## 再生タイミング

- **ステージ開始ジングル**: 新規ゲーム開始時・次ステージ進行時（`game_manager`）
- **エンジン音**: 移動キー押下中、8フレームごとに再トリガー（`player`）。
  サウンド長を8フレーム相当にすることで、キーを離すと自然に停止する。
- **発射音**: `can_fire()` を通過して実際に弾丸が生成された時のみ（`game_manager`）。
  `player.handle_input` での押下時再生は廃止。

## 実装上の注意

- チャンネル番号のハードコードを禁止し、必ず `SOUND_CHANNEL_*` 定数を使用する。
- `pyxel.load()` がサウンドデータを上書きするため、リソース読み込み後に
  `init_sounds()` / `init_music()` を再実行する（既存仕様を維持）。
